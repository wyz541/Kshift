# Kshift v0.2.0

## 状态

这是 `v0.1.0` 之后的 Stable 发布。Server、macOS 和 source 进入 Stable 资产；iOS 没有 Apple Developer Program，仅做内部测试，不进入 Stable 资产。

## 平台

| 平台 | 最低版本 | 分发 |
| --- | --- | --- |
| macOS | 26.0 | ad-hoc 或 Developer ID 签名 DMG/ZIP |
| iOS | 26.0 | 仅内部测试；不进入 Stable 资产 |
| Server | PostgreSQL 18.x | 内网 macOS arm64 安装包 |
| Source | 不适用 | source archive |

所有 Stable 资产必须来自同一个 source commit，并绑定同一份 manifest 和 SHA-256。

## 本次变更

- Plan Depth 甘特图支持任务延期展示：保留原始计划、当前目标、原截止 marker、延期纹理和 `延期 N 天` 徽标。
- 新增 typed `RescheduleTask` 命令和 append-only 改期记录，保存前后日期、延期天数、原因、操作者和 revision。
- 任务详情显示当前排期、原始排期、累计延期、逾期后改期标记和改期历史。
- 增加任务改期编辑器，并将连续延期与普通任务依赖在视觉和无障碍语义上区分。
- 优化紧凑宽度下的甘特任务行布局，避免横向裁切。
- Protocol 只新增兼容字段；`kshift.v1` 包版本不变。

## 安装

1. 备份数据库。
2. 下载 Release manifest 和 `SHA256SUMS`。
3. 验证所有资产 SHA-256。
4. 验证 GitHub attestation。
5. 安装 server bundle 并执行迁移前备份检查。
6. 安装 macOS DMG 或 ZIP。
7. iOS 内部测试 build 只在受控环境安装，不属于 Stable 发布步骤。
8. 运行健康检查和 P0 流程。

## 已知限制

- 仅限内网。
- 不支持外部平台导入。
- 不提供高可用数据库承诺。
- macOS 使用 ad-hoc 签名；没有 Developer ID 和 notarization。
- 4 小时 RPO 和 4 小时 RTO。
- 暂不包含子任务联动和预计延期预测。

## 验证

- Server：PostgreSQL 18.x migration、backup/restore、LaunchAgent SIGKILL recovery 和日志检查。
- macOS：DMG/ZIP install、upgrade、uninstall、rollback、Liquid Glass、无障碍和性能检查。
- Runtime evidence：`release/evidence/server-runtime.json`、`release/evidence/macos-runtime.json`。
- Release：manifest、SBOM、provenance、attestation、SHA-256 和 same-Draft Promote。

## 回滚

1. 禁止移动 Stable 标签。
2. 禁止覆盖 Stable 资产。
3. 应用回滚使用已批准旧版本。
4. 数据库回滚使用迁移前备份。
5. 发布新的 patch 或 minor 版本修复问题。
